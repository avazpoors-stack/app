## ۰) اصول پایه (تصمیم‌های کاربر — user)
1. **آفلاین و آنلاین با هم ساخته می‌شوند، در راستای هم** — یک اپ واحد؛ هر بخش «آفلاین-اول» است و وقتی اینترنت هست با سرور همگام می‌شود.
2. **۱۰۰٪ تکمیل:** دارک‌مود و لایت‌مود در همه‌جا؛ جستجو در همه‌جا.
3. **هیچ شبیه‌سازی آماری نداریم** (user: «شبیه‌سازی نداریم») — اعداد ۲۰۰ کاربر از مسترپلن حذف شد؛ آمار فقط از کاربر واقعی می‌آید.
4. **خروجی نهایی شامل فایل APK اندروید است.**
5. **همه‌چیز اول ساخته می‌شود؛ خریدها آخر:** سرور، کلید نشان/زرین‌پال/پیامک و... فقط در انتها خریده می‌شوند و کاربر خودش آن‌ها را با راهنمای فارسی داخل کد می‌گذارد. پس **اپ و بک‌اند بدون هیچ کلیدی کامل کار می‌کنند** (حالت Mock برای هر سرویس پولی).
6. **فازبندی جدا** تا اشتباه نشود: هر فاز یک ماژول کامل با در خروجی قابل اثبات.
7. **بدون بازنویسی کد بین فازها:** لایه‌بندی سخت + قرارداد اینترفیس (بخش ۲.۵).
8. **کد سبک:** وابستگی کم، بدون فریم‌ورک سنگین، هدف حجم APK زیر ۵۰ مگابایت [assumed: هدف — اگر اشتباه: سقف عوض می‌شود].
9. **امنیت + راه‌اندازی آسان برای کاربر غیرفنی:** یک اسکریپت ساده برای بالا آوردن سرور + راهنمای فارسی قدم‌به‌قدم.

### ۲.۵ قرارداد اینترفیس (مکانیزم «بدون بازنویسی»)
- UI هرگز مستقیم به storage/شبکه دست نمی‌زند؛ فقط از **سرویس‌ها** (مثل `WorkoutRepository`, `AuthService`) استفاده می‌کند.
- هر سرویس دو پیاده‌سازی دارد: `Local` و `Remote` — سوییچ با وضعیت اینترنت؛ UI و مدل‌ها عوض نمی‌شوند.
- مدل‌های مشترک (exercise, session, product, venue, coach, user) در `core/models` می‌مانند.
- هر ماژول در پوشهٔ خودش (features/...)؛ هیچ ماژولی UI ماژول دیگر را import نمی‌کند.

### ۲.۶ امنیت (پیش‌فرض‌ها)
- HTTPS خودکار روی سرور (Caddy یا Nginx) [assumed]؛ رمز عبور hash شده؛ توکن کوتاه‌عمر؛ محدودیت درخواست؛ اعتبارسنجی ورودی (pydantic)؛ **هیچ کلیدی در گیت** — همه `${ENV_VAR}`؛ پشتیبان‌گیری روزانهٔ دیتابیس.

### ۲.۷ حالت بدون کلید (Mock) — شرط «همه‌چیز اول، خرید آخر»
- اپ و بک‌اند بدون هیچ کلید/خریدی کامل کار می‌کنند: OTP نمایشی (کد ثابت در dev)، نقشه placeholder، پرداخت غیرفعال با پیام «به‌زودی»، سینک محلی.
- هر کلید فقط از env/`--dart-define` خوانده می‌شود: `${NESHAN_API_KEY}`، `${ZARINPAL_MERCHANT_ID}`، `${KAVENEGAR_API_KEY}`، `${DB_PASSWORD}` و...

## ۳) فازها (هر فاز: در خروجی قابل اثبات + بدون بازنویسی)

### P0 — اسکلت دوطرفه (اپ + بک‌اند با هم)
- **Done when:** اپ Flutter با تم بام (دارک/لایت) و ۴ تب روی اندروید اجرا می‌شود؛ پروژهٔ FastAPI بالا می‌آید؛ `flutter test` و `pytest` سبز؛ CI در گیت‌هاب APK دیباگ می‌سازد.
- گام‌ها: ایجاد پروژهٔ Flutter؛ تم با توکن‌های رنگی؛ ناوبری؛ اسکلت بک‌اند (FastAPI + SQLite + health endpoint)؛ CI (تست + بیلد APK).

### P1 — هستهٔ تمرین (کاملاً آفلاین)
- **Done when:** چرخهٔ طلایی کامل (انرژی ← تمرین ← ثبت ست ← امتیاز/استریک ← کارت)؛ ۴ برنامهٔ JSON؛ تست‌های Alpha/Beta (مرز ۲۳:۵۹، Debounce، یادآور ۱۹:۳۰ در حالت هواپیما).
- بدون بازنویسی: محتوای JSON از `core/models` خوانده می‌شود تا در P2 بدون تغییر UI سینک شود.

### P2 — بک‌اند، حساب‌ها و سینک (در راستای P1)
- **Done when:** ثبت‌نام/ورود با نقش + OTP (Mock در dev)؛ پروفایل و تنظیمات (تم/تقویم شمسی)؛ دادهٔ تمرین آفلاین با سرور همگام می‌شود و برعکس؛ مهمانِ P1 همان کاربر لاگین‌شده می‌شود.
- بدون بازنویسی: فقط پیاده‌سازی Remote به سرویس‌ها اضافه می‌شود.

### P3 — جستجوی سراسری
- **Done when:** جستجو در حرکات/برنامه‌ها/محصولات/مکان‌ها/مربی‌ها زیر ۱ ثانیه [assumed: هدف — اگر اشتباه: ایندکس‌گذاری].

### P4 — مکان‌های ورزشی + نشان
- **Done when:** دسته‌بندی جدا؛ ثبت‌نام مکان با پنل؛ نقشه با نشان (بدون کلید: placeholder)؛ تعرفه‌ها.
- گام‌های نشان: ثبت‌نام رایگان در پنل توسعه‌دهندگان؛ ساخت کلید نوع «اپلیکیشن موبایل – android» با Package Name + SHA1 (verified: developers.neshan.org)؛ کلید فقط از `${NESHAN_API_KEY}`؛ پکیج Flutter نشان [assumed: اگر نبود، SDK اندروید با platform channel].

### P5 — فروشگاه
- **Done when:** دسته‌بندی درختی ورزشی؛ پنل فروشنده؛ سبد و سفارش؛ پرداخت (بدون کلید: پیام «به‌زودی»)؛ فیلترها.

### P6 — مربی‌هاب
- **Done when:** پروفایل مربی؛ برنامه‌دهی به مشتری؛ جلسات؛ تعرفه‌ها و رزرو.

### P7 — AI پاسچر (فاز فیزبیلیتی)
- **Done when:** اسپایک: عکس → landmark → پیشنهاد حرکات اصلاحی با برچسب «پیشنهاد تمرینی، نه ارزیابی پزشکی»؛ معیارهای رد/قبول از قبل نوشته شده؛ عکس‌ها روی گوشی می‌مانند (بسته به Q7).

### P8 — ریلیز و راه‌اندازی
- **Done when:** تست‌های Chaos (۳۰۰۰ کلیک) و حافظه/حجم؛ `flutter build apk --release --split-per-abi` + AAB؛ **`docs/SETUP_GUIDE_FA.md`**: راهنمای فارسی خرید سرور و کلیدها + جای‌گذاری در کد + ساخت APK نهایی؛ ممیزی امنیتی؛ ویدیوی ۲ دقیقه‌ای حالت هواپیما + Pitch Deck + نمونه JSON گزارش (verified: مسترپلن بخش ۷.۲).

## ۴) قوانین کد (سبک و بدون بازنویسی)
1. هر فاز: **تست قبل از کد** — فایل تست از قبل نوشته می‌شود، بعد پیاده‌سازی (قرمز → سبز).
2. هر ماژول فقط از سرویس‌های ماژول خودش + core استفاده می‌کند.
3. وابستگی جدید فقط با یک خط دلیل در PR؛ بدون فریم‌ورک سنگین.
4. دادهٔ واقعی کاربران هرگز وارد گیت نمی‌شود (قاعدهٔ ریپوی پژوهشی — verified).
5. کد نهایی هر فاز: `flutter analyze` بدون خطا + تست‌ها سبز.
6. هیچ کلید/رمز واقعی در کد؛ فقط `${ENV_VAR}`.
