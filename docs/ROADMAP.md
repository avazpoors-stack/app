### ۲.۵ قرارداد اینترفیس (مکانیزم «بدون بازنویسی»)
- UI هرگز مستقیم به storage/شبکه دست نمی‌زند؛ فقط از **سرویس‌ها** (مثل `WorkoutRepository`, `AuthService`) استفاده می‌کند.
- هر سرویس دو پیاده‌سازی دارد: `Local` (امروز) و `Remote` (فاز بعد) — پیاده‌سازی عوض می‌شود، UI و مدل‌ها نه.
- مدل‌های مشترک (exercise, session, product, venue, coach, user) در `core/models` می‌مانند و همهٔ ماژول‌ها از یک تعریف استفاده می‌کنند.
- هر ماژول در پوشهٔ خودش (features/...)؛ هیچ ماژولی UI ماژول دیگر را import نمی‌کند.

## ۳) فازها (هر فاز: در خروجی قابل اثبات + بدون بازنویسی)

### P0 — زیرساخت و اسکلت
- **Done when:** اپ روی اندروید اجرا می‌شود؛ ۴ تب + سوییچ دارک/لایت کار می‌کند؛ `flutter test` سبز است؛ CI در گیت‌هاب ساخته شد.
- گام‌ها: ایجاد پروژهٔ Flutter؛ تم با توکن‌های رنگی تم بام (نارنجی-خاکستری، دارک/لایت)؛ ناوبری ۴ تب؛ پکیج‌های پایه؛ تست اسکلت.
- بدون بازنویسی: تم و ناوبری از همین‌جا برای همهٔ ماژول‌ها.

### P1 — پیلوت آفلاین «بدنه» (اسکوپ تأییدشده)
- **Done when:** چرخهٔ طلایی کامل (انرژی ← تمرین ← ثبت ست ← امتیاز/استریک ← کارت)؛ ۴ برنامهٔ JSON؛ تست‌های Alpha/Beta (مرز ۲۳:۵۹، Debounce، یادآور ۱۹:۳۰ در حالت هواپیما)؛ `dart run tool/simulate_200_users.dart`؛ **APK ریلیز ساخته شد**.
- بدون بازنویسی: محتوای JSON از `core/models` خوانده می‌شود تا در P3 بدون تغییر UI سینک شود.

### P2 — هویت و نقش‌ها
- **Done when:** ورود/ثبت‌نام با انتخاب نقش (مشتری/فروشنده/مکان/مربی/ادمین) + OTP پیامکی؛ پروفایل؛ ذخیرهٔ تم دارک/لایت و تقویم شمسی.
- بدون بازنویسی: مهمانِ P1 همان کاربرِ لاگین‌شدهٔ P2 می‌شود (AuthService با حالت Guest).

### P3 — همگام‌سازی و جستجو
- **Done when:** داده‌ها آفلاین-اول سینک می‌شوند (بدون تغییر UI)؛ جستجوی سراسری زیر ۱ ثانیه [assumed: هدف — اگر اشتباه: ایندکس‌گذاری در فاز بعد].
- بدون بازنویسی: فقط پیاده‌سازی Remote به سرویس‌ها اضافه می‌شود.

### P4 — مکان‌های ورزشی
- **Done when:** دسته‌بندی جدا (استخر/باشگاه/رزمی/یوگا/...)؛ ثبت‌نام مکان با پنل؛ نقشهٔ نشان با آدرس؛ تعرفه‌ها؛ جستجوی مکانی.
- بدون بازنویسی: venue به‌عنوان ماژول جدید، بدون دست‌زدن به M1–M3.

### P5 — فروشگاه
- **Done when:** دسته‌بندی درختی ورزشی (دیجی‌کالایی ولی ورزشی)؛ پنل فروشنده؛ سبد خرید و سفارش؛ پرداخت زرین‌پال؛ فیلترها.
- بدون بازنویسی: ماژول جدا؛ سبد محلی → آنلاین با همان سرویس.

### P6 — مربی‌هاب
- **Done when:** پروفایل مربی؛ برنامه‌دهی (انتساب برنامه به مشتری)؛ جلسات؛ تعرفه‌ها و رزرو.
- بدون بازنویسی: از برنامه‌های M1 و نقش‌های M2 استفاده می‌کند.

### P7 — AI پاسچر (فاز فیزبیلیتی)
- **Done when:** اسپایک: عکس → landmark → پیشنهاد حرکات اصلاحی با برچسب «پیشنهاد تمرینی، نه ارزیابی پزشکی»؛ معیارهای رد/قبول از قبل نوشته شده.
- بدون بازنویسی: سرویس AI جدا؛ خروجی فقط به مدل‌های core وصل می‌شود.

### P8 — عرضه و پولیش
- **Done when:** ممیزی دارک/لایت و عملکرد؛ حجم APK زیر سقف؛ خروجی APK + AAB؛ کیت حامی (ویدیوی حالت هواپیما، Pitch Deck، نمونه JSON گزارش) — (verified: مسترپلن بخش ۷.۲).

## ۴) قوانین کد (سبک و بدون بازنویسی)

4. دادهٔ واقعی کاربران هرگز وارد گیت نمی‌شود (قاعدهٔ ریپوی پژوهشی — verified).
