# بک‌اند «بدنه» (FastAPI)

بک‌اند پلتفرم ورزشی «بدنه» — فاز P2: حساب‌ها (۵ نقش)، OTP (Mock در توسعه)، سینک آفلاین-اول.

## راه‌اندازی (توسعه)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
```

سرویس روی `http://127.0.0.1:8000` بالا می‌آید؛ مستندات تعاملی در `/docs`.

## متغیرهای محیط

همه از env خوانده می‌شوند (نمونه: `.env.example`). در حالت `production` مقدار `JWT_SECRET`
الزامی است؛ تا کلید کاوه‌نگار را در `KAVENEGAR_API_KEY` نگذاری، OTP در حالت Mock است
(کد در پاسخ `POST /api/v1/auth/otp/request` نمایش داده می‌شود — فقط برای توسعه).

## API (پیشوند `/api/v1`)

| مسیر | روش | توضیح |
|---|---|---|
| `/auth/otp/request` | POST | درخواست کد تأیید (rate-limit: ۱/دقیقه، ۵/ساعت) |
| `/auth/otp/verify` | POST | تأیید کد → ساخت/ورود حساب + توکن‌ها |
| `/auth/login` | POST | ورود با شماره + رمز (اگر هنگام ثبت‌نام رمز گذاشته باشی) |
| `/auth/refresh` | POST | تازه‌سازی توکن (چرخشی؛ قبلی ابطال می‌شود) |
| `/auth/logout` | POST | خروج و ابطال رفرش |
| `/auth/me` | GET/PUT | پروفایل: نام، لحن، برنامهٔ فعال |
| `/sync/push` | POST | ارسال رکوردهای تمرین + پروفایل (آخرین‌تغییر-برنده) |
| `/sync/pull?since=ISO` | GET | دریافت تغییرات از یک زمان |
| `/sync/claim` | POST | انتقال دادهٔ مهمان به حساب (یک‌بار) |
| `/admin/audit` | GET | لاگ ممیزی (فقط ادمین) |

## نقش‌ها (RBAC)

`customer | seller | venue | coach | admin` — هنگام تأیید OTP (فقط کاربر جدید) انتخاب می‌شود؛
نقش ادمین فقط برای پنل مدیریت (مثل `/admin/audit`) است.

## امنیت (P2)

- هش رمز: argon2 · JWT کوتاه‌عمر (۱۵ دقیقه) + رفرش چرخشی (۷ روز)
- OTP: انقضا (۱۲۰ ثانیه)، حداکثر ۵ تلاش، محدودیت ارسال
- rate-limit درون‌حافظه برای OTP، ورود، تأیید کد و رفرش؛ اعتبارسنجی pydantic در همهٔ ورودی‌ها
- لاگ ممیزی (بدون دادهٔ شخصی) در جدول `audit_log` — فقط ادمین می‌بیند؛ عبور از حد نرخ با `ratelimit.hit` ثبت می‌شود
- هیچ کلیدی در کد؛ فقط env

### سیاست رمز عبور

هنگام **تعیین** رمز (ثبت‌نام با رمز) این قواعد اجرا می‌شود — `PasswordValidator` در `app/schemas.py`:

- حداقل ۸ و حداکثر ۱۲۸ کاراکتر
- حداقل یک حرف بزرگ، یک حرف کوچک و یک عدد
- رمزهای خیلی رایج (مثل `Password1`) رد می‌شوند

در **ورود** این قواعد عمداً اعمال نمی‌شود تا سیاست رمز به مهاجم لو نرود و کاربران قدیمی قفل نشوند.

### محدودیت نرخ (rate limit)

همهٔ قواعد در یک جا تعریف شده‌اند (`_rate_limit_rules` در `app/auth.py`):

| scope | قواعد |
|---|---|
| `otp_request` | ۱/دقیقه و ۵/ساعت به‌ازای شماره · ۱۰/ساعت به‌ازای IP |
| `otp_verify` | ۵/۱۵دقیقه به‌ازای شماره · ۳۰/۱۵دقیقه به‌ازای IP |
| `login` | ۵/۱۵دقیقه به‌ازای شماره · ۲۰/۱۵دقیقه به‌ازای IP |
| `refresh` | ۶۰/۱۵دقیقه به‌ازای IP |

پاسخ عبور از حد: `429` با پیام فارسیِ شاملِ زمان تقریبی انتظار.

## مهاجرت دیتابیس (Alembic)

**توسعه/تست:** جدول‌ها خودکار ساخته می‌شوند (`init_db()`).
**تولید:** `init_db()` عمداً خطا می‌دهد؛ فقط مهاجرت:

```bash
# اعمال آخرین نسخه
DATABASE_URL=postgresql+psycopg://... .venv/bin/alembic upgrade head

# بعد از تغییر مدل‌ها: ساخت مهاجرت جدید
.venv/bin/alembic revision --autogenerate -m "توضیح تغییر"

# دیدن SQL بدون اجرا (بازبینی قبل از تولید)
.venv/bin/alembic upgrade head --sql

# برگشت یک قدم
.venv/bin/alembic downgrade -1
```

آدرس دیتابیس داخل `alembic.ini` نیست و از `DATABASE_URL` خوانده می‌شود
(یا `-x db_url=...`)، تا اطلاعات اتصال وارد گیت نشود.
تست `tests/test_migrations.py` تضمین می‌کند مهاجرت‌ها با مدل‌ها همگام بمانند.
